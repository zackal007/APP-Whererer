10个月73460星，这个开源技能专查真人怎么说

这一年，给 AI 装技能成了新潮流。技能列表越拉越长，真正决定产出质量的，反而是它动手之前去哪儿找材料。

想查一个产品最近口碑怎么样，搜索引擎给的多半是编辑写好的稿子和厂商自己的页面。真人这一个月在论坛里怎么吐槽、在评论区怎么吵，恰恰是最难翻到的那部分。

最近发现一个开源技能 last30days，专治这件事：先去真人扎堆的地方把最近 30 天的讨论捞回来，再让 AI 动笔。

GitHub：https://github.com/mvanhorn/last30days-skill

它是一个给 AI Agent 用的调研技能，装在 Claude Code、Codex、Cursor 这类宿主里运行。今年 1 月 23 日创建，目前已斩获 73460 Star、6480 个 Fork，MIT 协议开源，更新很勤，11 月 17 日到 22 日连发了五个版本，最新是 v4.6.0。

▍装上技能，一行命令

先看怎么装。我用的是 Claude Code 推荐的那条路，在对话框里敲一行 /plugin marketplace add mvanhorn/last30days-skill，marketplace 会把版本和更新都管起来，新版本出来自动刷新。

不在 Claude Code 生态也没关系。它走的是开放的 Agent Skills 标准，一行 npx skills add mvanhorn/last30days-skill -g 就能装到 Codex、Cursor、Copilot、Gemini CLI 等 50 多个宿主上；用 Grok 的有 grok plugin install，用 claude.ai 网页版的可以下载 .skill 文件上传，Claude Desktop 则拖一个 .mcpb 包进设置页。

一个小提醒：两种安装方式别叠着用，Claude Code 不会去重，/last30days 会出现两个条目。一台机器选一条路就好。

▍铺开信源，专挑真人

装完直接给它一个话题，比如某个产品名、某个技术概念。它会同时铺开 Reddit、X、YouTube、Hacker News、Polymarket、TikTok、Instagram 和普通网页，把最近 30 天的内容捞回来。

我看中的是它的排序逻辑：信源不是按搜索引擎的权重排，而是按真实用户的参与度打分——帖子的点赞、评论、转发这些真人留下的痕迹越重，越往前排。编辑部写得再工整的稿子，也压不过一条被顶了几千次的真实吐槽。

细节上也能看出是真下过功夫的：YouTube 不是只看标题和简介，它会搜完整字幕，从 45 分钟的视频里只摘真正值得引用的那几句；TikTok 和 Instagram 的热门评论也会单独成行，附在它支撑的结论下面，必要时带翻译。这些平台的内容平时根本进不了搜索引擎，是只有刷到的人才知道的信息。

捞回来的材料还会带上出处。最后合成的那份简报，每段判断后面能追到原帖，不是 AI 凭印象编的综述。

▍查家公司，顺藤摸瓜

真正让我提起兴趣的，是它查公司的方式。给它一个公司名，它不光翻讨论，还会去读这家公司当月的专利申请和招聘页面：哪个新职位在招、岗位描述里漏了什么还没公布的方向，都给你标出来。等于公司自己还没官宣，路线图先被自家招聘启事卖了。

上市公司还多一行行情：过去 30 天股价对比标普 500、最大单日波动，配上 Polymarket 上相关的预测概率。拿它在开会前查一个人、发布前查一家公司，捞到的东西确实是搜索引擎首页给不了的——有个例子里，一条 227 个赞同的 Reddit 评论点破了某工具迟早被封的判断，这种话永远不会出现在官方博客上。

它还有个发现模式：直接问最近 AI Agent 圈什么在爆发，它会先扫各平台的热榜，再让 Agent 评审、过滤，最后给出 5 到 10 个按增长速度排序的话题，连每个话题后续怎么深挖的命令都配好。做选题的人看到这儿，应该已经心动了。

▍跑完一轮，合成简报

一轮跑完，产出的不是链接堆，是一份带结论的研究简报：这个话题最近在升温还是降温、支持和反对的声音各说什么、哪些是事实哪些只是情绪。

对做产品的人来说，这个顺序是对的。以前是 AI 先写结论、再回头找证据；到它这儿反过来了，先把真实讨论摆上桌，再让 AI 汇总。拿它查竞品口碑、查用户最近在骂什么，比自己开十几个标签页翻论坛快得多。

它还有个细节我觉得贴心：第一次运行会弹出一个 30 秒的配置向导，把能解锁的免费信源一次配好，不用先啃文档。

▍不配密钥，也能起步

门槛比想象中低。Reddit（含评论）、Hacker News、Polymarket、GitHub 这几个源不用任何配置就能用，arXiv、Techmeme、Yahoo Finance 由向导自动装免费 CLI 解锁，公司类话题还能查到专利申请和招聘页面。

想把信源铺满，就得掏自己的钥匙：X 要填官方 API 的 Bearer Token，YouTube 等平台也要各自的密钥或浏览器令牌。各平台互不相通，这是这类工具绕不开的成本，好在它把每个源要什么、多少钱都列成了表，密钥存在系统钥匙串或本地配置文件里，不经第三方。

▍看清边界，别踩坑

先说最实在的一条：X 的官方 API 默认只能查最近一周左右的帖子，除非你的开发者项目有完整归档权限。所以“最近 30 天”这个口径，在 X 这个源上是要打折的，简报里涉及 X 的结论，心里要留个心眼。

其次是凭据不互通。Claude Desktop 和 Claude Code 的密钥是两套存储，你在 Code 里配好的，到了 Desktop 还得再输一遍，这是它有意的设计，但第一次用确实容易在这儿愣住。

另外，Claude Desktop 的安装包目前还没覆盖 Windows，Windows 用户先用其他宿主。还有前面提过的重复安装问题，两种装法叠用，命令列表里会出现两个同名条目。

顺带一提，它有个 --preflight 预检命令：真正开跑前，先把这次会读哪些配置、会写哪些文件列给你看，不读 Cookie、不落盘。对要拿它查竞品的人来说，这种先亮底牌再动手的设计，算个实打实的加分项。

▍写在最后

让 AI 先去听真人说话、再开口总结，这个顺序值得所有做调研的人借鉴。last30days 把这件事做成了一个能装进 50 多个宿主的开源技能，零配置就能跑起一半信源，这是它 10 个月冲到 73460 星的原因。

如果你是产品经理或者独立开发者，要定期看竞品口碑和用户风向，建议从零配置那几个源开始，先跑一个你最熟的话题，拿结果和你自己的判断对一对，准不准一轮就知道。

如果你在团队里维护 AI 工作流，它的多宿主安装方式值得研究：一份技能，Claude Code、Codex、Cursor 同时认，省了给每个工具单独适配的功夫。

如果你是做内容的，它的发现模式可以直接当选题雷达用：话题还没在公众号和热搜上冒头时，先在 Reddit 和 Hacker News 的热榜里露出苗头，按增长速度排好的清单，基本就是一份提前两三天的选题会材料。
